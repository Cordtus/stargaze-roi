## Project Overview

Stargaze ROI Tracker measures the return on a ~700K ATOM grant (Proposal #1017) given to Stargaze for migrating their NFT marketplace to Cosmos Hub. It tracks gas fee revenue generated by all Stargaze-related CosmWasm contracts, converts fees to USD using CoinGecko prices, and displays progress toward the $1.5M target.

The tracker uses direct gRPC queries to Cosmos Hub archive nodes via libyaci (reflection-based gRPC client). No dependency on external indexers.

## Architecture

```
cmd/tracker/main.go     Entry point, wires components together
internal/
  chain/                gRPC client (libyaci), contract discovery with DB cache
  config/               TOML config parsing, DATABASE_URL env override
  processor/            Polls chain for contract txs, records fee revenue with dedup
  price/                CoinGecko API client with rate limiting and caching
  server/               HTTP API (/api/stats, /api/transactions, /health)
  db/                   PostgreSQL schema, migrations, and queries (roi_tracker schema)
static/                 Frontend HTML/CSS/JS
```

### Contract Discovery

On startup, the tracker expands 4 seed contract addresses by:
1. Querying `ContractInfo` for each seed -> gets code_id and creator
2. Querying `ContractsByCode` for each code_id -> finds all sibling contracts
3. Querying `ContractsByCreator` for each creator -> finds all deployed contracts

This discovers ~5058 contracts total (10 unique code_ids). Results are cached in `discovered_contracts` table. High-volume passive contracts (e.g., 5043 WL Merkle whitelists, code 417) are skipped for tx querying since their instantiation txs are captured via parent factory contracts.

### Deduplication

Transactions are deduped by tx_hash. A single tx can involve multiple contracts (e.g., factory instantiating a child contract), so the same tx might appear in queries for different contracts. The DB enforces `UNIQUE(tx_hash)`.

## Database Design

The tracker creates a `roi_tracker` schema in its PostgreSQL database:

- `sync_state` - Cursor tracking (last processed block height)
- `discovered_contracts` - Cached contract discovery results (address, code_id, creator, label)
- `processed_burns` - Fee transactions with USD values (deduped by tx_hash)
- `price_cache` - CoinGecko price cache (1-minute granularity)
- `stats_cache` - Aggregated stats (auto-updated via trigger)

## Configuration

Edit `config.toml` or set `DATABASE_URL` environment variable. Key settings:

- `contract.addresses` - Seed contract addresses (discovery expands from here)
- `contract.skip_code_ids` - Code IDs to skip for tx querying (captured via parent)
- `contract.start_height` - Block height to begin indexing from
- `target.usd_amount` - Grant target for progress calculation
- `discovery.refresh_minutes` - How often to re-discover contracts (0 = startup only)
- `coingecko.rate_limit_per_minute` - API rate limit (free tier: 10-30/min)
